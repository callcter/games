# 全量玩法调研：难度阶梯 · 有解性保证 · 玩法说明（2026-09-19）

覆盖全部 24 款游戏，逐款核对 core 实现与 scene 现状。所有结论带代码位置，供下一轮迭代直接引用。

## 二、有解性保证分级

**A. 生成时强验证（9 款）**
- 水排序：`solvePath`（启发式 DFS，25 万节点）验证存在解路径且落在档位步数带，140 次尝试后用测试验证过的静态备用局（加载时自检，无效即 throw）。core L329-360
- 停车场：BFS（与走子同源的转移函数）步数带过滤 + 5/8/17 步备用关。core L115-166
- 数独：随机挖空逐格 `countSolutions===1` 回填验证。core L105-118
- 叠叠消：构造式（几何→合法移除拓扑序→花色映射），洗牌救援用同拓扑序重建保证仍可解。core L139-265
- 接水管：随机 DFS 生成树的位掩码即 solution，cells 恒为解的旋转。core L16-32
- 七巧板：目标即标准拼法（天然可解），`intersectionArea` 精确多边形相交判定覆盖/重叠。core L22-71
- 迷宫：DFS 生成树全连通，生成即有解。core L4-17
- 解绳结：外平面图 + 凸位置目标，存在零交叉布局。core L21-30
- 推箱子：30 关全部 `solve` BFS 可解，PAR 表与最优步数逐关相等（tests/sokoban L13-17 锁死）。后 20 关为固定种子生成+BFS 筛选。

**B. 外部结论保证（1 款）**
- 空当接龙：微软 32000 编号局中随机（跳过唯一无解局 11982），代码自身不做求解验证。

**C. 局部保证（2 款）**
- 扫雷：首点及 8 邻不布雷（首点必开一片），整体局面不保证免猜。
- 泡泡龙：换弹只从场上现存颜色抽取（杜绝无效色死等），但不检测"剩余可达三连"死局。

**D. 无保证（12 款）**
- 纸牌随机类（经典纸牌/蜘蛛）：发牌纯随机。经典纸牌有 `stuck()` 死局提示（但漏判一种走法，见四.2）；蜘蛛无任何死局检测。
- 纯随机品类（2048/俄罗斯方块/合成水果/五子棋/点泡泡/红包雨/打地鼠/切水果）：品类如此，靠撤销/重开兜底，合理。

## 三、横切发现（系统性问题）

### 1. 玩法说明普遍缺失（用户已点名要求全量补齐）
现状四档分布：
- **完全没有**：2048、五子棋、记忆翻牌、叠叠消、水排序（水排序连游戏目标都没有文案，最严重）
- **仅一行状态行/操作提示**：俄罗斯方块、合成水果、扫雷、七巧板、接水管、推箱子、泡泡龙、解绳结、迷宫、数织、数独、三款纸牌
- **选难度面板 headline 一句**：动作四款（切水果另有滑动手势动画教学，是标杆）
- **"怎么玩"按钮**：仅停车场（次标杆：目标句常驻 + 轻点亮出全部合法目标格）

### 2. 默认档与档位露出不一致
- 动作四款默认**进阶**（`newGame(mode=1)`，pop-bubbles/core L21），益智九款默认基础——同一个孩子进门先遇到"进阶"，与"孩子能独立玩"的第一优先级不符
- core 支持但 UI 无入口：数独 4×4（对低龄最有价值）、迷宫 5×5、解绳结 5 点、接水管 3×3、记忆翻牌 8 对
- core 默认参数与 UI 脱节（易误导后续维护）：记忆翻牌 core 默认 8 对（UI 无此档）、泡泡龙 core 默认 3 色（从未使用）、数独 core 默认 9（UI 默认 6）

### 3. 节奏机制不一致
- 点泡泡/红包雨有 pace 渐快（60 秒内最多 +35%），打地鼠/切水果没有——四款同为限时动作游戏，后期紧张度曲线不齐

## 四、逐款优化方案

### P0：玩法说明系统（全部 24 款）
统一方案（复用 UI Foundation 的 dialog 组件）：
1. 共享帮助组件：顶栏"?"图标按钮 + 图文说明面板（目标一句话 / 操作方式 / 难度差异 / 计分规则，每款 3-5 行短句）
2. 首次进入自动弹出一次（localStorage `family-game-room-help-seen-v1` 记游戏级标记），之后只从"?"进入
3. 接入点：puzzle-kit 场景、action-kit 场景、三款纸牌与俄罗斯方块/合成水果/2048 的独立场景、叠叠消/水排序的独立场景，各挂一份；文案集中在各游戏一个 `help.ts` 常量
4. 动作四款已有 headline，升级为面板（切水果的手势教学动画保留并作为其他三款的模板）
5. 水排序、叠叠消、2048、记忆翻牌、五子棋这五款从零补目标说明

### P1：难度阶梯补齐与统一
| 项 | 方案 |
|---|---|
| 动作四款默认档 | 默认改"基础"（或保留进阶但需产品确认；与益智游戏统一） |
| 数独 4×4 档 | UI 补"4×4 入门"按钮（core 已完整支持含测试），恢复逻辑同步 |
| 迷宫 5×5 / 解绳结 5 点 / 接水管 3×3 / 记忆翻牌 8 对 | 补 UI 入口或从 core 白名单与成绩档位中正式退役（二选一，避免 core/UI 漂移）；低龄向建议补齐 5×5 迷宫与 8 对翻牌 |
| 数独同尺寸难度 | 6×6/9×9 内按挖空数分轻松/标准（挖空数是现成参数） |
| 数织 50 幅 | 加选图页（完成 flags 数据已存在，只缺 UI），替代纯线性"下一幅" |
| 2048 | 补"小小版 3×3 / 经典 4×4 / 宽敞版 5×5"三档（BOARD_SIZE 参数化，core 改动极小） |
| 经典纸牌 | 补"翻一（现有）/ 翻三（经典难）"两档 |
| 五子棋 | AI 分"简单（现状启发式）/ 认真（必堵活三/跳三+双威胁检测）"两档，仍保持可注入随机源可测 |
| 俄罗斯方块 | 起始等级选择（1/5/10），替代无手动档的现状 |
| 打地鼠/切水果 | 补 pace 渐快（与另两款动作游戏同曲线） |
| 合成水果 | 难度档暂不加（物理堆叠内生难度已足够），仅在玩法说明中解释危险线 |

### P2：规则层修复（小而准）
| 游戏 | 问题 | 修复 |
|---|---|---|
| 经典纸牌 | `stuck()`（core L153-173）漏判"列牌上基础堆"走法，可能误报死局 | 列循环内对每段头补 `canDropOnFoundation` 检查 |
| 切水果 | 炸弹 -5 秒写死在 scene L210，core 只返回计数（规则层不完备） | 扣时下沉 core（MODES 加 `bombPenaltyMs`，state 加 timeLeft 由 core 扣） |
| 推箱子 | "提示一步"超 5 万节点预算返回 null 时，文案误报"箱子被困住"（scene L88） | 区分"超时"与"确认无解"两种返回；超时提示"这局太复杂，试试别的路" |
| 解绳结 | 胜利隐藏约束"点距≥45px"（core L19）不满足时无任何反馈 | 无交叉但点距不足时状态行提示"有两个点靠得太近，再拉开一点" |
| 泡泡龙 | 无死局检测（场上无可消组合时只能自己发现） | settle 后检测"剩余颜色存在可达三连"否则提示撤销/重开 |
| 停车场 | 生成期挡路竖车 y 抽样（core L134）可能不挡出口行，浪费尝试 | y 直接取 EXIT_ROW 相邻可挡位（不影响正确性，仅提升生成效率） |
| 蜘蛛纸牌 | 撤销历史无截断（klondike 有 200 条上限） | 与 klondike 对齐加上限 |
| 空当接龙 | 无法指定局号（只有随机/重开） | 结果面板加"局号"显示 + 家长输入重玩指定局（可选） |

### P3：锦上添花（可选）
- 扫雷高级档（30×16，格 22px）在手机上触控偏难：固定 680px 画布改为按视口自适应或加捏合缩放
- 记忆翻牌双人模式加"回合开始提示谁的回合"动效（现状仅状态行）
- 数织 5×5 → 10×10 之间加 7×7 过渡尺寸（现有关卡库无此尺寸，需新增图案）
- 大厅卡片长按直达"玩法说明"（配合 P0 帮助系统）

## 五、建议实施顺序

1. **第一批（P0）**：帮助系统组件 + 24 款文案接入（纯增量、低风险、用户点名）
2. **第二批（P1 前半）**：动作四款默认档统一 + 数独 4×4 + 迷宫 5×5 + 数织选图页
3. **第三批（P2）**：七个规则层修复（各自带复现测试，遵循"先测试后实现"）
4. **第四批（P1 后半）**：2048 三档 / 纸牌翻三 / 五子棋 AI 分档 / 方块起始等级（产品行为变更，交付时需明示）
