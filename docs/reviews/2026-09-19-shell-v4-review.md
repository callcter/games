## 架构重点与待复现项

- 保持 core、存档格式、玩法与依赖不变；本批修 UI 集成，不借机重写所有场景。
- `puzzle-kit` / `action-kit` 共用 768 宽、900–1680 高的挂载和内容平移；
  `createPuzzleChrome` 属于屏幕层；纸牌及独立场景仍有自己的尺寸、布局职责。
  “共享组件”不等于所有场景已完成一致的布局约束。
- `scene-modal.ts` 的旧弹窗在 POST_STEP 恢复时无条件删除当前弹窗映射。
  需复现同帧关闭再打开后是否失去单例保护；确认后先补回归，再修复归属判断。
- 继续核对 fluid 内容坐标、动作游戏结算与旋转、共享按钮命中/抬手行为。
  未复现项不能混写为已修复。

## 验收计划

开发期间只做目标复现和类型检查；共享层稳定后一次 `pnpm check`。
以 2048/五子棋/俄罗斯方块（RESIZE）、扫雷（固定 FIT）、水管/动作游戏（fluid）
覆盖不同接入方式；三组全量截图只在最终布局上刷新。生命周期若修改，追加完整浏览器
和帮助专项。生产截图与生产离线检查使用 preview，不能依赖浏览器导入 `/src/`。

## 修复与实测记录

本节在每项修复完成、取得证据后更新；未运行的命令不得预填通过。

### 追加确认（旋转专项）

- **UI-04 / P1**：在同一场景依次切换 390×844 → 768×1024 → 1024×768，
  水管的圆形按钮及方格明显拉长。`puzzle-kit/mount.ts`、`water-sort/index.ts`、
  `tile-match/index.ts` 在 FIT 模式调用 `scale.resize`；本地 Phaser 4.2.1
  `ScaleManager.js` 明确要求 FIT 基准尺寸变更使用 `setGameSize` 以更新显示宽高比。
  修复后断言 CSS / 逻辑 / backing canvas 比例相同，旋转保留棋盘，并操作旋转后的棋盘。
- **UI-05 / P2**：水管横屏状态胶囊中心 142、高 44，难度按钮中心 165、高 60，
  两者实际覆盖。共享 PuzzleScene 需要紧凑顶栏布局，在内容第一行之前留出完整间隔，
  不能用把全部内容向下移到画布外的方式掩盖。长屏仍保持原有内容平移。

- **UI-06 / P1 已复现**：`browser-modal-regression.mjs` 在同帧关闭第一个弹窗、打开第二个，
  等 POST_STEP 后再调用打开，实测得到 **2 个**原生模态（预期 1 个）。旧关闭回调误删新弹窗
  的 WeakMap 归属。保留失败断言，修复仅允许当前实例删除自己的映射。
- UI-04 的失败断言同时落地：水管旋转后 CSS 比例 `0.85333`，逻辑比例 `0.46209`，
  backing canvas 比例 `0.46200`，证明不是截图查看器缩放造成。

- **UI-07 / P2 已复现**：动作回合结束后旋转，结果卡仍停在创建时的中心 `y=450`，
  逻辑画布已高 `1662`；遮罩也未跟随。`showGameDialog` 没有 resize 生命周期。
  修复共享结果卡重排并在销毁时解绑；验证旋转后的再来一次和监听器基线。

- **UI-08 / P2 已确认**：关闭手机俄罗斯方块帮助后，390 宽因 `panelWidth=0` 完全不画
  得分、下一个及暂存牌；仅靠初次帮助截图没有发现。保持棋盘/规则不变，在窄屏顶栏下
  提供紧凑成绩和预告行；宽屏继续用侧栏。补验暂存后牌型展示、直落计分与旋转后操作。
