# 小树游戏屋 · 多设备 UI 截图集

给下一轮 UI 迭代（GPT 审计）用的全量截图。生成方式：`pnpm build && pnpm preview`
后运行 `node scripts/capture-gallery.mjs`（本地生产构建 + 独立无头 Chrome，
进入每个 hash 路由等待入场动画完成再截图；动作游戏先点难度进入真实回合）。

## 目录结构

| 目录 | 设备视口 | 说明 |
| --- | --- | --- |
| `phone-390x844/` | 主流手机竖屏 390×844（DPR 2） | 大厅自动两列；`home.png` 为整页长图 |
| `ipad-768x1024/` | iPad 竖屏 768×1024（DPR 2） | 基准验收尺寸 |
| `ipad-1024x768/` | iPad 横屏 1024×768（DPR 2） | 固定比例游戏横放时画布居中留白属预期，但留白区应有背景延伸或方向建议，不应是纯黑/错位 |

每组 25 张：`home.png`（大厅）+ 24 款游戏各一张（文件名 = 路由 ID，
对应 `src/app/app.ts` 与 `src/app/puzzles.ts` 注册表）。

## 审计时请重点核查的历史问题区

这些是过去真实翻过车的地方，新截图请优先验证同类问题：

1. **图标渲染**：圆形按钮内必须有可辨认的 glyph（箭头/喇叭/撤销弯箭头/灯泡等），
   不允许空圆盘。2026-09-18 之前曾因 SVG 无显式宽高导致纹理 0×0 全部空白。
2. **背景变形**：背景图必须等比铺满，不允许拉伸压扁（水排序背景曾被纵向压扁 34%）。
3. **Phaser 4 hitArea**：容器交互区用 `[0,size]` 本地坐标；中心对称 hitArea
   会导致按钮只剩中心单像素可点——截图看不出，改动按钮代码时必须核。
4. **手机两列与触控目标**：390 宽大厅两列卡片、按钮逻辑高 ≥60px、单指可完成全部操作。
5. **横竖屏**：竖屏比例游戏在 1024×768 下应完整可玩（居中留白 + 非阻塞方向建议），
   不得强制旋转或重开棋局。
6. **文字与遮挡**：文案简体中文、不重叠、结果面板不遮挡操作。
7. **液体观感**（水排序）：试管应是连续液柱 + 弯月面，不允许「格子感」分层块。

## 技术背景速览

- 纯静态 PWA（Vite + Phaser 4.2 + TypeScript），无后端无追踪，孩子（iPad/手机）使用；
- 两套场景基座：`puzzle-kit`（768×900 FIT 回合制）与 `action-kit`（逐帧限时回合）；
  叠叠消/水排序是独立的 portrait-fluid 场景（逻辑高随宿主 960~1720 自适应）；
- 共享 UI 层 `src/ui/`（tokens + Phosphor 图标 + 按钮/胶囊/对话框组件），
  叠叠消与水排序已迁移，其余游戏仍是各自绘制——审计时可对照两者风格差异，
  评估下一批游戏是否继续迁移。
- 游戏清单与规则见仓库根 `AGENTS.md` 第 2、8 节。
