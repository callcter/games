# 小树游戏屋 · 多设备 UI 截图集

每组 25 张：大厅 + 注册表中的 24 款游戏；三组为 390×844、768×1024、1024×768，
DPR=2。大厅是整页长图，游戏是视口截图。`manifest.json` 记录生成时间、源码提交、
未提交源码差异摘要、生产入口摘要和逐图状态。生成成功不代表视觉验收通过。

```bash
pnpm build
pnpm preview --host 127.0.0.1 --port 4173 --strictPort
# 另一个终端：
node scripts/capture-gallery.mjs
```

脚本自己启动并清理临时 Chrome，不需要另开 9222，也不允许连接用户日常浏览器。
可用 `GALLERY_BASE` 指定生产 preview 地址、`GALLERY_OUT` 指定输出目录。
运行结束后仍须关闭自己启动的 preview。

采用明确的“已读帮助、新局”截图 fixture：每组清空脚本临时浏览器的存档并重返大厅；
帮助已读标记来自 Node 侧注册表，不向生产页注入开发模块；动作游戏点基础难度，
推箱子点第一关，其余截取新棋盘。它用于检查游戏布局，不覆盖新用户首弹、续玩提示、
胜负或旋转后的动态行为。这些另由浏览器专项检验，不能靠预置已读状态跳过帮助验收。
路由不符、缺页、弹窗遮挡、浏览器异常、资源错误或等待超时必须失败。

审查时须实际打开每张图，放大可疑区域；特别看标题/按钮/状态/难度的间隔、完整棋盘、
底部操作和背景比例。还要在同一场景旋转并实际操作：重新载入三个尺寸无法发现旋转后
比例失真或命中偏移。本轮问题和证据见
[审查台账](../docs/reviews/2026-09-19-shell-v4-review.md)。

当前架构：`puzzle-kit` 和 `action-kit` 共享逻辑宽 768、逻辑高 900–1680 的 fluid
挂载。内容保留旧 768×900 坐标，通过容器平移和 `legacyPoint` 换算；顶栏独立于内容。
2048/五子棋/俄罗斯方块/扫雷接入共享顶栏，但保留各自棋盘布局；水排序/叠叠消有独立
fluid 布局，纸牌和合成水果保留固定比例场景。共享 UI 并不意味着尺寸与生命周期已统一。

v5-E 起，大厅默认不是“24 张卡片全部铺开”。默认首页按：

```text
继续玩（有最近记录时）
→ 最近玩过
→ 四个玩法分类
→ 游戏柜预览（全部分类默认前 8 款）
→ 查看全部
```

组织。Gallery 的 `home.png` 应截取这个真实默认状态；不要为了截图自动点击“查看全部”。
24 款游戏本身仍分别有独立截图，因此完整游戏覆盖没有减少。
